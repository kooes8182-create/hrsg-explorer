## 7. 추가 개선 권장사항

1. **실제 자료 연결 순서**: 플랜트 운전 데이터 → 승인 성능 모델·계수 → 운전 한계표. 그 전까지 결과는 DEMO 로만 사용.
2. **기본값 정합성**: 목표 회수 출력을 출력 손실 범위 안으로 조정하거나, 출력 손실 계수의 근거를 확인.
3. **평가셋 v2**: 사용자 피드백·정답 라벨로 업로드 문헌 범위까지 포함한 평가셋을 만들고, dev 에서만 조정 → test 1회.
4. **Gemini 답변 정확도 평가**: 검색 recall 과 별개로 답변 정확도·인용 정확도를 사람이 검토하는 절차.
5. **메모리**: 8 GB 에서 BGE-M3 를 두 앱이 동시에 올리지 않도록 한 쪽 검색만 사용하거나 임베딩 서비스를 분리.
6. **접근성 전수 검사**: axe 등 도구로 WCAG AA 점검 (도구 설치 필요).
7. **정식 CI**: 서버 테스트·빌드·e2e 를 커밋마다 자동 실행.

## 10. 통합 알림 센터 (2026-11-04)

- **서버가 만드는 알림만**: 새 Django 앱 `notifications` (PostgreSQL `Notification` 테이블). 상태형(STATE)은 저장된 입력·계산 결과·체크리스트·실측값·검색 상태에서 '지금 참인 조건'을 계산해 새 조건은 만들고, 사라지면 해결 처리 + 복구 사건을 남김. 같은 상태가 이어지는 동안 새로 만들지 않음. 사건형(EVENT)은 계산 완료·결과 저장·수급 변경·세정 필요도 지수 상승처럼 API 성공 시점에 1회.
