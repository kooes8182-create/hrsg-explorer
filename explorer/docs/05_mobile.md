# 모바일 웹 (Mobile Engineering Dashboard)

현장 엔지니어가 휴대폰으로 **상태 확인 · 알림 · 현장 점검 · AI 질문**을 하도록 만든 모바일 화면입니다.
PC 웹과 **같은 코드·같은 서버(Django 8002)·같은 DB(hrsg_explorer)** 를 씁니다. 가상 데이터 기반 로컬 데모이며 실시간 설비 감시·운전 판단 시스템이 아닙니다.

## 1. 실행과 접속

```bash
# 1) 백엔드 (이 컴퓨터 전용, 그대로)
cd explorer/backend && .venv/bin/python manage.py runserver 127.0.0.1:8002
# 2) PC 웹 (이 컴퓨터 전용, 그대로)
cd explorer/frontend && npm run dev            # http://localhost:5174
# 3) 휴대폰 접속용 서버 (모바일 웹)
cd explorer/frontend && npm run dev:mobile     # http://<이 컴퓨터의 와이파이 IP>:5175
```

- 휴대폰을 **같은 와이파이**에 연결하고, `npm run dev:mobile` 이 출력한 `Network:` 주소(예: `http://172.29.56.122:5175`)를 엽니다.
  컴퓨터 IP 확인: `ipconfig getifaddr en0`
- macOS 방화벽이 켜져 있으면 처음 실행할 때 node 의 들어오는 연결을 허용할지 묻습니다 → 허용해야 휴대폰에서 열립니다.
- 화면 선택: **5175 로 열고 화면 폭 ≤ 767px(휴대폰)** 일 때만 모바일 화면. 태블릿·PC 폭은 PC 화면. **PC 주소 5174 는 창을 줄여도 항상 PC 화면.**
  모바일 화면의 전체 메뉴 → 'PC 화면으로 보기' 로 바꿀 수 있고, 다시 '모바일 화면으로 보기' 로 돌아옵니다.

## 2. 네트워크·보안 구성

| 구성 | 설정 |
|---|---|
| 휴대폰 접속용 서버 | `vite.mobile.config.ts` — `0.0.0.0:5175`, **사설망 주소만 허용**(127/10/172.16–31/192.168/169.254, IPv6 사설·링크로컬). 그 밖의 주소는 403 |
| API | 5175 의 `/api` 를 `127.0.0.1:8002` 로 전달(`changeOrigin`) → Django `ALLOWED_HOSTS`(localhost·127.0.0.1) 변경 없음 |
| PC 웹·백엔드 | 5174 `localhost`, 8002 `127.0.0.1` 그대로 — 와이파이 주소로는 접속 불가 (검증함) |
| CORS/CSRF | 같은 출처(프록시)라 CORS 불필요. 로그인·세션이 없어 CSRF 대상 요청 없음 (DRF 인증 클래스 비어 있음) |
| 외부 전송 | 기존과 같음: Gemini 에는 검색된 문단(≤8)·가린 질문·서버 계산값만. **현장 사진은 서버 폴더에만 저장하고 AI·외부로 보내지 않음** |

> ⚠️ 이 데모에는 **로그인·권한·HTTPS 가 없습니다.** 같은 와이파이에 있는 누구나 5175 로 열 수 있습니다. 공용 와이파이에서는 켜지 마세요.
> 실제 사내 데이터를 연결하려면 사용자 인증, 역할별 권한, HTTPS(사설 인증서 또는 사내 프록시), 접속 기록, 사진·데이터 보존 정책이 별도로 필요합니다.
> 인터넷 공개 배포(Render 등)는 이번 범위에서 승인되지 않았습니다.

| 하단 메뉴 | 주소 | 내용 |
|---|---|---|
| 홈 | `/dashboard` | 운전 상태(정상·주의·위험·미확인 + DEMO 표시, 데이터 기준·마지막 계산 시각), KPI 4개(배압·스택 온도·출력 손실·데이터 수령률, 전체 지표 시트), 현재 확인할 항목(미해결 알림 3), 성능 추이 미니 차트(서버 값만), 세정 효과 요약(결과 있을 때만), 빠른 작업 |
| 알림 | `/notifications` | 분류 탭(전체·위험/주의·데이터·분석·시스템), 현재/미해결/해결 이력, 상세 시트(관련 수치·기준값·발생 조건·확인 사항·출처·DEMO), AI 설명 요청, 읽음 ≠ 해결 |
| 점검 | `/checklist` | 진행률 3종 + 필수 미수신, 범주·상태 필터·필수만·검색, 항목 카드, 상세 입력 시트(값·단위·위치·조건·시각·수급·검증·메모·검토), 현장 사진, 자료 요청 초안(복사·공유, 발송 없음) |
| AI | `/ai-assistant` | PC 와 같은 대화·추천 질문, 열었던 화면 맞춤 질문, 근거는 답변 아래 접기(논문 카드 → 원문 문단), 대화 기록 시트 |
| 전체 메뉴 | 시뮬레이션·계산기·심층 분석·세정 전후·RAG 지식베이스·RAG 평가·참고 자료·설정 | 계산기는 모바일 요약(결과 먼저·입력 요약·계산 근거·스냅샷·AI 질문, 상세 입력은 펼치기). 나머지는 PC 화면을 반응형으로 그대로 사용 |

## 4. 데이터 공유·동시 수정

- 모든 저장은 서버 DB 기준. 모바일 입력은 PC 체크리스트에, PC 대화는 모바일 AI 기록에 그대로 보입니다.
- 체크리스트 저장 시 화면이 불러온 `updated_at` 을 함께 보내고, 다른 기기가 먼저 바꿨으면 409 로 거부 → '최신 값 다시 불러오기'. (PC 화면은 기존처럼 보내지 않으므로 동작 변화 없음)
- 오프라인: 연결 없음 안내 + 마지막으로 받은 값 유지(마지막 조회 시각 표시). **오프라인 입력 저장은 충돌 정책이 없어 구현하지 않음.**

## 5. 테스트

```bash
npm run e2e          # PC 회귀 (5174)
npm run e2e:mobile   # 모바일 (5175, 390×844) — M01~M19
```

실제 iPhone Safari·Android Chrome 기기 검사는 하지 않았습니다(Chrome 모바일 화면 흉내로만 검사). 기기에서 확인할 항목: 안전 영역(노치·홈 막대), 화면 키보드가 열릴 때 AI 입력창 위치, 카메라 촬영 후 업로드, HEIC 미리보기(Chrome 은 HEIC 표시 불가 — 저장은 됨).
