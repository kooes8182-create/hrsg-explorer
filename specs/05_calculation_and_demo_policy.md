# 05. 계산 및 데모 정책

> **Phase 6 갱신**: 공개 문헌 기반 '참고 추정'(basis `REFERENCE_ESTIMATE`)과 IAPWS-IF97 핀치·어프로치 참고 계산, 공개 SMP 참고값을 추가했습니다. 근거·규칙: [11_public_references.md](11_public_references.md). 승인 모델(실제 평가)은 계속 미연동입니다. 아래 §5(핀치 산출 불가)는 §11 규칙으로 대체되었습니다.

## 0. 공통 원칙
1. **계산은 Django 서버의 `backend/calculators/` 에서만** 합니다. 프론트엔드는 입력을 보내고 결과를 그립니다.
2. **결정성**: 같은 입력이면 항상 같은 결과. 난수·현재 시각을 계산에 쓰지 않습니다(`computed_at` 기록만 예외).
3. **입력 누락은 0이 아닙니다.** 누락이면 해당 결과를 `null` 로 두고 `reason` 에 누락 항목을 적습니다.
4. **만들지 않는 것**: 비공개 성능 산정식, 오염도 지수, 실제 운전 한계값(경보·트립 임계값), 핀치·어프로치 기준값, 실제 제조사 모델 데이터.
5. 모든 결과에 `basis`(근거 종류), `model_version`, `data_source`, `computed_at`, 입력 조건을 붙입니다.

| basis | 화면 배지 | 의미 |
|---|---|---|
| `DEMO_FIXED` | 데모 예시값 | 가상 시나리오의 고정 결과 |
| `USER_ASSUMPTION` | 사용자 가정 기반 계산 | 사용자 가정값으로 한 단순 산술 |
| `UNAVAILABLE` | 산출 불가 | 모델·기준·입력이 없어 계산하지 않음 |
| `REEVALUATION_REQUIRED` | 재평가 필요 | DEMO 입력이 바뀌어 예시 결과를 쓸 수 없음 |
| `REFERENCE_ESTIMATE` | 공개 문헌 참고 추정 | 공개 문헌·표준 식으로 계산한 참고값 (승인 모델 아님, specs/11) |

## 1. 계산 모듈 구조 (실제 모델 교체 대비)

```
backend/calculators/
├── base.py            # 결과 자료형, 공통 검증, Unavailable 헬퍼
├── demo_scenarios.py  # DEMO 시나리오 고정 입력·결과 (가상)
├── performance.py     # get_performance_model() → DemoScenarioModel | NotConnectedModel
├── economics.py       # 사용자 가정 기반 단순 경제성 계산
└── pinch_approach.py  # 현재는 항상 산출 불가
```

```python
class PerformanceModel:            # 실제 모델이 생기면 이 인터페이스로 구현해 교체
    version: str
    def evaluate(self, operating_values: dict) -> dict: ...

class NotConnectedModel(PerformanceModel):
    version = "NOT-CONNECTED"      # 항상 null + 사유
```

- 실제 모델은 서버에서만 실행되며, 모델 파일·계수·식은 응답과 로그에 포함하지 않습니다.
- REAL 모드는 `NotConnectedModel` 을 직접 사용합니다. 실제 모델이 생기면 `performance.py` 의 REAL 분기만 교체합니다(모델 선택용 환경변수는 지금 만들지 않음).

## 2. 성능 평가

### 2.1 경로
| 모드 | 동작 |
|---|---|
| **DEMO** | 사용자가 **명시적으로 고른** 가상 시나리오의 고정 입력과 고정 예시 결과를 반환. `model_version = "DEMO-SCENARIO-v1"`, `data_source = "가상 데모 시나리오 (실제 설비·운전 한계 아님)"` |
| **REAL** | 승인된 계산 모델 미연동. 모든 결과 `null`, `basis = UNAVAILABLE`, `reason = "승인된 계산 모델이 연동되지 않아 결과를 산출할 수 없습니다."`, `model_version = "NOT-CONNECTED"`. 입력값과 누락 항목 목록은 그대로 보여줌 |

### 2.2 DEMO 시나리오 (모두 가상 값)

가스터빈 모델명은 모든 시나리오에서 `DEMO-GT`(가상). 아래 숫자는 **화면 확인용 가상 값이며 실제 설비 상태·운전 한계·성능을 뜻하지 않습니다.**

| 운전값 key | 단위 | DEMO-NORMAL | DEMO-ALARM | DEMO-TRIP |
|---|---|---|---|---|
| `gt_model` | — | DEMO-GT | DEMO-GT | DEMO-GT |
| `gt_load` | % | 100 | 100 | 100 |
| `ambient_temp` | °C | 15 | 15 | 15 |
| `gt_exhaust_temp` | °C | 600 | 601 | 602 |
| `gt_exhaust_flow` | kg/s | 650 | 650 | 650 |
| `gt_back_pressure` | kPa | 3.9 | 4.8 | 5.5 |
| `hrsg_dp` | kPa | 3.4 | 4.2 | 4.9 |
| `stack_temp` | °C | 95 | 104 | 112 |
| `steam_flow` | t/h | 300 | 292 | 284 |

(Phase 6) 차압 수준은 공개 세정 사례(POWER 2015: 세정 전 약 19.5 in H2O ≈ 4.86 kPa, 세정 후 약 13.2 in H2O ≈ 3.29 kPa)를 참고한 가상 값입니다.
시나리오마다 참고 추정 입력(청정 기준 차압 3.3 kPa, 세정 후 기대 차압 3.3 kPa, 가스터빈 출력 160 MW, 모두 가상)이 함께 들어갑니다.

고정 예시 결과 (같은 입력의 문헌 참고 추정 범위 안에서 정한 가상 값):

| 결과 | DEMO-NORMAL | DEMO-ALARM | DEMO-TRIP |
|---|---|---|---|
| 운전 상태 | `NORMAL` (정상) | `ALARM` (경보) | `TRIP` (트립) |
| 판단 근거 | "데모 시나리오에 지정된 상태입니다. 실제 판정 기준이 적용되지 않았습니다." | 동일 | 동일 |
| 예상 성능 손실 | 0.1 MW (참고 범위 0.07~0.16) | 1.0 MW (참고 범위 0.61~1.45) | `null` — "트립 상태 데모 시나리오에는 성능 손실 예시값이 없습니다." |
| 세정 후 회수 효과 | 0.1 MW | 0.8 MW (참고 범위 0.61~1.45) | `null` — 같은 사유 |

- 상태 판정은 **시나리오에 지정된 값**이며, 운전값과 임계값을 비교하는 로직을 만들지 않습니다.
- 시나리오를 바꾸면(정상 → 경보 → 트립) 서버가 해당 고정 결과를 즉시 반환하고 화면이 바로 바뀝니다.

### 2.3 입력 변경 시
- 선택한 시나리오의 운전값 중 **하나라도 다르면**(값 수정·비움 포함):
  - 운전 상태 `null`(판정 보류), 손실·회수 `null`
  - `basis = REEVALUATION_REQUIRED`
  - `reason = "입력 변경으로 재평가 필요 / 실제 모델 미연동"`
- 이전 예시 결과를 그대로 보여주지 않습니다. [시나리오 값으로 되돌리기] 를 누르면 다시 `DEMO_FIXED`.
- 비교는 숫자 값 기준(문자열 "3.0"과 3 은 같은 값). 서버가 판단합니다.

## 3. 결과 표시 단위
| 항목 | 단위 | 반올림 |
|---|---|---|
| 출력·손실·회수 | MW | 소수 1자리 |
| 금액 | 원 | 정수 (천 단위 구분 기호) |
| 발전량 | kWh | 소수 3자리까지 (MW × 1,000 = kW) |
| 온도 / 압력 | °C / kPa, MPa | 입력 그대로 |

## 4. 경제성 — 사용자 가정 기반 계산

검증된 성능 예측이 아닙니다. 모든 결과에 **"사용자 가정 기반 계산"** 배지와 아래 안내를 붙입니다.
> "일정한 회수 출력과 SMP를 가정한 단순 비교입니다. 실제 순이익이나 검증된 성능 예측이 아닙니다. SMP는 공식 가격이 아닌 입력값입니다."

(Phase 3 요청으로 갱신: 정지 손실·추가 비용 항목 추가, 공법은 가상 공법 A/B 고정, 회수 기간은 계산하지 않음)

### 4.1 입력 (`economics_assumptions`)
| 경로 | 이름 | 단위 | 검증 |
|---|---|---|---|
| `smp` | SMP | 원/kWh | ≥ 0 |
| `methods.{A,B}.recovered_mw` | 회수 출력 | MW | ≥ 0 |
| `methods.{A,B}.operating_hours` | 세정 후 예상 운전 시간 (**세정 정지 시간 제외**) | h | ≥ 0 |
| `methods.{A,B}.cleaning_cost` | 세정 비용 | 원 | ≥ 0 |
| `methods.{A,B}.extra_cost` | 정지 손실 및 추가 비용 (세정 비용에 포함되지 않은 것만) | 원 | ≥ 0 |
| `methods.{A,B}.extra_cost_included` | 정지 손실·추가 비용이 세정 비용에 이미 포함됨 | bool | true 이면 `extra_cost` 는 비워야 함(아니면 400, 중복 차감 방지) |
| `sources.{경로}` | 값 출처 | `USER` / `DEMO` | `DEMO` 는 데모 예시값과 같을 때만 인정, 그 외는 `USER` |

- 공법은 **가상 공법 A/B** 두 개로 고정합니다. 실제 업체명·공식 가격을 넣지 않습니다.
- [데모 값 채우기] 는 서버의 `ECONOMICS_EXAMPLE`(가상 값)을 채우고 출처를 `DEMO` 로 표시합니다. 사용자가 바꾼 칸은 `USER` 가 됩니다.
- DEMO 성능 결과의 회수 효과를 자동으로 가져오지 않습니다(데모 예시값과 사용자 가정을 섞지 않음).
- 빈 칸은 0으로 바꾸지 않습니다. 그 값이 필요한 결과만 `null` + "입력 필요: …" 사유를 돌려줍니다.
- 화면은 입력이 바뀌면 결과를 즉시 가리고, 0.7초 뒤 자동 저장·계산합니다. 서버가 400을 주면 해당 칸에 오류를 표시합니다.

### 4.2 계산식 (공개 산술, 공법별)
```
추가 발전량(kWh)          = 회수 출력(MW) × 1,000 × 세정 후 예상 운전 시간(h)
추가 발전 매출(원)         = 추가 발전량(kWh) × SMP(원/kWh)
입력 비용 반영 순편익(원)   = 추가 발전 매출 − 세정 비용 − 정지 손실 및 추가 비용
                           (extra_cost_included 이면 마지막 항은 빼지 않음)
```
- 운전 시간은 이미 정지 시간을 뺀 값이므로 정지 시간을 다시 빼지 않습니다. 정지로 인한 손실은 금액으로만 한 번 반영합니다.
- 계산은 `Decimal` 로 하여 같은 입력에 같은 결과를 보장합니다. 금액은 원 단위 반올림, 음수 순편익은 그대로 표시합니다.
- 예 (데모 값): A = 1.5 MW, 4,000 h, SMP 120, 세정 300,000,000, 추가 50,000,000
  → 6,000,000 kWh, 매출 720,000,000 원, 순편익 370,000,000 원
  B = 1.0 MW, 4,200 h, 세정 150,000,000, 추가 20,000,000 → 4,200,000 kWh, 504,000,000 원, 334,000,000 원
- 순편익이 가장 큰 공법에 "가정 기준 순편익 최대" 표시. "추천"이라는 표현은 쓰지 않습니다.
- `model_version = "USER-ASSUMPTION-CALC-v1"`, `data_source = "사용자 입력 가정값 (일부 데모 값 포함 가능)"`

## 5. 핀치·어프로치

- 입력: `drum_pressure`(MPa), `eco_outlet_water_temp`(°C), `evap_outlet_gas_temp`(°C). 체크리스트 값 불러오기 가능.
- 일반적 정의(교과서 수준):
  핀치 = 증발기 출구 가스 온도 − 드럼 압력의 포화 온도,
  어프로치 = 드럼 압력의 포화 온도 − 절탄기 출구 급수 온도.
- 포화 온도를 구하려면 **검증된 물성(증기표) 계산**이 필요하고, 판정에는 **기준값**이 필요하지만 둘 다 승인·제공되지 않았습니다.
- 따라서 현재는 입력이 다 있어도 결과 `null`, `basis = UNAVAILABLE`,
  `reason = "검증된 물성 계산과 판정 기준값이 없어 산출할 수 없습니다."`
  입력이 빠졌으면 누락 항목도 함께 사유에 적습니다.
- 임의 근사식(포화온도 근사 등)을 넣지 않습니다.

## 6. 결과 저장
- [평가 실행] 시 서버가 계산 → `CalculationResult` 저장 → 응답.
- 결과 조회 시 현재 저장된 입력과 결과의 `inputs_snapshot` 을 kind별 범위([03](03_data_model.md) CalculationResult)로 비교해 다르면 `stale: true` 로 알리고, 화면은 그 결과를 "재평가 필요"로 가립니다.
- 화면에서 저장 전에 입력을 바꾸면 서버 응답을 기다리지 않고 해당 결과를 즉시 "재평가 필요"로 가립니다(화면은 계산하지 않음).
