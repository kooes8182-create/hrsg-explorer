# 02. UI/UX 명세

## 1. 디자인 원칙
- 업무용 대시보드. **밝은 배경 + 절제된 파란색**(Bootstrap `primary` 계열) 기본.
- 읽기 쉬운 글자(본문 16px 이상), **핵심 수치는 크게**, 수치 옆에 **단위를 항상** 표시.
- 상태는 **색상 + 텍스트**를 함께 사용 (색만으로 구분하지 않음).
- 화면에는 구현 기술 설명을 노출하지 않고 **사용자의 다음 행동**을 안내합니다.
- Bootstrap 5 컴포넌트만 사용. 별도 UI 프레임워크·차트 라이브러리를 추가하지 않습니다(게이지·도식·막대는 SVG로 직접 작성).

## 2. 레이아웃

```
┌────────────┬──────────────────────────────────────────────┐
│ HRSG 레퍼런스│ [케이스 선택 ▾] [+ 새 케이스]   [DEMO 배지] [KO|EN] [☀/☾] │
│            ├──────────────────────────────────────────────┤
│ 1 평가 개요  │                                              │
│ 2 데이터 준비 │                 본문                          │
│ 3 성능·경제성 │                                              │
│ 4 AI 질문하기 │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- 데스크톱(≥ 992px): 왼쪽 고정 사이드바 + 오른쪽 본문.
- 모바일(< 992px): 사이드바는 상단 햄버거 메뉴(Bootstrap offcanvas)로 접힘.
- 라우트: `/overview`, `/data`, `/evaluate`, `/ask` (기본 `/overview`)

## 3. 공통 표시 요소

| 요소 | 규칙 |
|---|---|
| 모드 배지 | 상단에 항상 표시. `DEMO — 가상 시나리오` (주황 테두리) / `실제 평가 — 모델 미연동` (회색) |
| 결과 근거 배지 | 결과 카드마다: `데모 예시값` / `사용자 가정 기반 계산` / `산출 불가` / `재평가 필요` |
| 운전 상태 | 정상(초록, ● 정상) / 경보(주황, ▲ 경보) / 트립(빨강, ■ 트립) / 판정 보류(회색, — 판정 보류). 아이콘 모양도 달리해 색약 사용자도 구분 |
| 체크리스트 상태 | 미수신(회색) / 수신(파랑) / 검증 완료(초록) + 텍스트 |
| 초안 표시 | 체크리스트 제목 옆 `계획서 기반 초안`, 필수 표시 옆 `임시 기준` |
| 데모 답변 | AI 답변마다 `데모 답변` 배지 |

## 4. 성능·경제성 평가 화면

- **PC: 입력(왼쪽 5/12) | 결과(오른쪽 7/12)** 나란히, **모바일: 입력 → 결과** 세로.
- 입력 영역
  - 모드 선택(DEMO / 실제 평가). DEMO에서는 시나리오 선택(정상 / 경보 / 트립 — 모두 가상).
  - 운전값 입력 칸: 시나리오를 고르면 고정값이 채워짐. 값을 수정하면 (저장 전이라도) 즉시 결과 영역이 `재평가 필요` 로 바뀌고 이전 결과 수치는 가려짐. [시나리오 값으로 되돌리기] 버튼 제공.
  - 경제성·핀치 입력도 같음: 바꾸는 즉시 해당 결과만 `재평가 필요` 로 가림.
  - 경제성 가정값 입력(05 §4): SMP, 운전 시간, 공법별 비용·가정 회수 출력.
  - 핀치·어프로치 입력: 드럼 압력, 절탄기 출구 급수 온도, 증발기 출구 가스 온도 (체크리스트 값 불러오기 버튼).
- 결과 영역 (위에서 아래로)
  1. **운전 상태 카드**: 큰 상태 표시 + 판단 근거 또는 판정 보류 사유
  2. **게이지 2개**: GT 배압, HRSG 차압 — 바늘 위치만 표시하고 경보·트립 구간 눈금은 그리지 않음(실제 한계값 미확보). 눈금 범위 0–6 kPa 는 표시용이며 "운전 한계 아님"을 함께 표기. DEMO 값에는 "가상 값" 표기
  - 화면 배치(Phase 3): 성능 / 경제성 / 핀치 세 구역이 각각 "입력(왼쪽 5/12) | 결과(오른쪽 7/12)" 한 줄. 모바일에서는 각 구역이 입력 → 결과 순서로 세로 배치
  - 비교 그래프 색: 공법 A `#2a78d6`/다크 `#3987e5`, 공법 B `#eb6834`/다크 `#d95926` (색각 이상 검사 통과). 범례·값 라벨·숫자 표를 함께 제공
  3. **HRSG 도식** (아래 §5)
  4. **예상 성능 손실 / 세정 후 회수 효과** 카드: 큰 숫자 + 단위, 값이 없으면 "산출 불가" + 사유
  5. **공법별 비용·편익 비교**: 표 + 가로 막대(비용 vs 편익, 순편익). `사용자 가정 기반 계산` 배지
  6. **핀치·어프로치** 카드: 입력값 표시 + "산출 불가" + 사유
  7. **계산 정보**: 입력 조건 표(값·단위), 계산 시점, 데이터 출처, 모델/데모 버전

## 5. HRSG 도식 (SVG)

```
 [가스터빈] ══배기가스══► [ HRSG: 과열기 │ 증발기(드럼) │ 절탄기 ] ══► [굴뚝]
    ⓟ GT 배압                ⓟ 입구        ⓟ 출구  → ΔP(차압)        Ⓣ 굴뚝 온도
                              ▲ 증기 ─────► (스팀터빈)
                              │
                         급수 ─┘ (절탄기 입구)
```

- **가스 흐름**(GT 배기 → HRSG → 굴뚝): 왼→오른, 주황/회색 굵은 선.
- **급수·증기 흐름**: 오른→왼(절탄기 → 증발기 → 과열기), 파랑 가는 선, 다른 화살표 모양.
- **GT 배압**과 **HRSG 차압(ΔP)** 은 서로 다른 측정점으로 그리고 라벨도 따로 표시.
- 측정값이 있으면 라벨에 값·단위, 없으면 "—"(0 표시 금지).
- 범례에 "가스 흐름 / 급수·증기 흐름" 표시. 정적 도식이며 애니메이션은 넣지 않음.

## 6. 그래프 제한
- 실제 데이터가 없는 **시계열(추세) 그래프는 만들지 않습니다.**
- 그래프는 공법별 비교 막대와 게이지만 사용합니다.

## 7. 언어
- 한국어 기본, 상단 `KO | EN` 전환. 선택은 `localStorage` 에 기억.
- UI 문자열은 `frontend/src/i18n/ko.js`, `en.js` 사전 객체로 관리 (추가 라이브러리 없음).
- 서버가 만드는 문구(사유, 요청문, 데모 답변)는 요청의 `lang` 값으로 언어를 고름.

## 8. 테마
- 라이트(기본) / 다크. Bootstrap 5.3 `data-bs-theme` 속성 사용, 선택은 `localStorage` 에 기억.
- 두 테마 모두 본문 대비 4.5:1 이상. SVG 색은 CSS 변수로 지정해 테마를 따름.

## 9. 화면 상태

| 상태 | 표시 |
|---|---|
| 로딩 | 스피너 + "불러오는 중…" |
| 빈 화면 | 케이스 없음: "평가 케이스를 먼저 만드세요" + [새 케이스]. 질문 이력 없음: 예시 질문 버튼 |
| 데이터 부족 | "다음 항목이 비어 있어 계산할 수 없습니다: …" + [데이터 준비로 이동] |
| 입력 오류 | 해당 칸 아래 빨간 안내(예: "숫자를 입력하세요", "0보다 커야 합니다") — 서버 400 응답의 필드 오류를 그대로 연결 |
| 서버 연결 실패 | 상단 경고 띠: "서버에 연결할 수 없습니다. 백엔드 서버가 켜져 있는지 확인한 뒤 다시 시도하세요." + [다시 시도]. 앱은 멈추지 않음 |
| 저장 성공/실패 | 짧은 토스트 메시지 |
