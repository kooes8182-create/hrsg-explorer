# 07. 검증 기준

- **자동**: Django 테스트(`python manage.py test`)로 검증
- **수동**: 브라우저에서 사람이 확인 (Phase 보고서에 확인 여부를 적고, 확인하지 못했으면 "미실행")
- 실제 검증 사례와 공식 테스트 질문 세트가 없으므로, 여기 기준은 **데모 PoC 검수 기준**입니다.

## 1. 계획서 검수 시나리오 대응

| # | 계획서 시나리오 | 이번 PoC 합격 기준 | 방법 |
|---|---|---|---|
| 1 | 같은 조건으로 계산 반복 → 결과 항상 동일 | 시나리오 3개 × 10회, 경제성 예시 입력 × 10회 결과(`result`)가 모두 동일 | 자동 |
| 2 | 검증용 사례 → 기대 결과 일치 | 05 §2.2 고정 결과, 05 §4.2 예시(A 6,000,000 kWh · 매출 720,000,000원 · 순편익 370,000,000원)와 일치. **실제 사례 검증은 미완료(자료 미제공)** | 자동 |
| 3 | 정상 → 경보 → 트립 화면 즉시 변경 | 시나리오 전환 시 상태 카드 텍스트·색·아이콘이 바뀜. 입력 수정 시 즉시 "재평가 필요" | 자동(API) + 수동(화면) |
| 4 | 테스트 질문 20개, 정답률 80% 이상, 근거 없는 수치 0건 | 데모: 기대 의도 일치 ≥ 16개, 근거 없는 수치 0건 (자동). **실제 LLM 정답률은 미검증** — [10](10_qa_acceptance_20.md) §5 | 자동 + 향후 사람 채점 |
| 5 | 한국어·영어 질문 → 질문 언어로 응답 | §3 의 ko 10개는 한국어, en 10개는 영어 답변 | 자동 |
| 6 | 민감 정보 요청 → 노출 0건 | 계산식·원문·고객사·API 키 요청 질문에 거절 답변, 답변에 비밀값·식 문자열 없음 | 자동 |
| 7 | 네트워크·키 오류 → 앱이 멈추지 않고 안내 | 백엔드를 끈 상태에서 각 메뉴 진입 시 연결 실패 안내 표시, 다시 켜면 [다시 시도]로 복구 | 수동 |
| 8 | 라이트/다크, PC/모바일 레이아웃 | 4개 메뉴 × (라이트·다크) × (1280px·390px)에서 가로 스크롤·겹침 없음 | 수동 |

## 2. 요구사항 추가 검증

| ID | 기준 | 방법 |
|---|---|---|
| R1 | 케이스 생성 시 체크리스트 30개 항목이 값 `null`, 상태 `MISSING` 으로 생성 | 자동 |
| R2 | 값 입력만으로 상태가 바뀌지 않음. 값 없는 항목을 `VERIFIED` 로 바꾸면 400 | 자동 |
| R3 | 미수신 필터, 진행률 숫자가 실제 항목 수와 일치 | 자동 |
| R4 | 요청문에 미수신 항목만 포함, "계획서 기반 초안" 문구 포함, ko/en 모두 생성 | 자동 |
| R5 | REAL 모드 성능 평가: 모든 결과 `null` + 사유, `basis=UNAVAILABLE` | 자동 |
| R6 | DEMO 입력 하나 수정 → `REEVALUATION_REQUIRED`, 예시 결과 미반환. 되돌리면 `DEMO_FIXED` | 자동 |
| R7 | 경제성: 가정값 누락 시 0으로 계산하지 않고 `null` + 누락 항목 사유. 음수 입력·숫자 아닌 입력은 400. MW→kWh(×1,000) 변환, 음수 순편익 그대로 표시, "세정 비용에 포함" 시 정지 손실 중복 차감 없음 | 자동 |
| R8 | 핀치·어프로치: 입력이 모두 있어도 `null` + 사유 | 자동 |
| R9 | 화면 이동 후 입력 유지, 저장 후 새로고침 시 복원 | 수동 |
| R10 | DEMO/실제 표시가 모든 메뉴 상단에 보임, 결과 카드마다 근거 배지 | 수동 |
| R11 | 프론트엔드 빌드 결과(`dist/`)에 계산식 함수·`.env` 값이 없음 (`grep` 확인) | 자동(명령) |
| R12 | `.env` 와 `reference/*.pdf` 가 `git status` 에 나타나지 않음 | 자동(명령) |
| R13 | 화면·코드·시드에 실제 제조사·발전소·고객사 이름이 없음 | 수동 + `grep` |
