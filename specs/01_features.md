# 01. 기능 명세

성능·경제성 계산 규칙은 [05](05_calculation_and_demo_policy.md), AI 질문하기는 [06](06_ai_qa.md) 에 있습니다.

## 1. 평가 케이스

| 기능 | 내용 |
|---|---|
| 생성 | 이름(필수), 메모(선택). 생성 시 체크리스트 초안 항목이 **값이 빈 상태로** 복사됨 |
| 선택 | 상단 선택기에서 케이스 전환. 마지막으로 고른 케이스 id는 브라우저 `localStorage` 에 기억 |
| 이름·메모 수정 | 가능 |
| 삭제 | (2026-10-19 사용자 요청으로 추가) 평가 개요의 [케이스 삭제]. 케이스 이름을 그대로 다시 입력해야 삭제되며, 서버도 이름을 확인합니다. 체크리스트·입력값·결과·질문 이력이 함께 지워지고 되돌릴 수 없습니다. 가상 예시 케이스를 지운 뒤 `seed_demo_cases` 를 실행하면 다시 만들어집니다. |

- 체크리스트, 계산 입력값, 계산 결과, 질문 이력은 모두 케이스에 연결되어 DB에 저장됩니다.
- **입력 유지 규칙**
  - 화면을 이동해도 입력 중인 값은 프론트엔드 상태(케이스별)에 남아 있습니다.
  - [저장] 을 누르면 서버 DB에 저장되고, 새로고침·재실행 후에도 복원됩니다.
  - 저장하지 않은 변경이 있으면 화면에 "저장되지 않은 변경 있음"을 표시합니다.

## 2. 평가 개요 (메뉴 1)

현재 케이스에 대해 다음을 보여줍니다. 숫자는 모두 서버 `/overview/` 응답에서 옵니다.

1. **데이터 준비 상태**: 전체 진행률(검증 완료 / 수신 / 미수신 개수), 범주별 진행률
2. **평가 가능 여부** (평가 기능별)

   | 평가 기능 | 표시 예 |
   |---|---|
   | 성능 평가 (실제) | "산출 불가 — 승인된 계산 모델 미연동" (체크리스트와 무관하게 항상) + 필수 항목 준비율(임시 기준) |
   | 성능 평가 (DEMO) | "가능 — 가상 시나리오" |
   | 경제성 (사용자 가정) | 가정값 입력 완료 여부 |
   | 핀치·어프로치 | "산출 불가 — 검증된 물성 계산·기준값 없음" + 입력 항목 준비율 |

3. **다음에 할 일**: 규칙 기반 안내 문구 최대 3개
   - 미수신 필수 항목이 있으면 → "데이터 준비에서 미수신 항목 N개 요청문 복사"
   - 수신했지만 검증 안 된 항목이 있으면 → "수신 항목 N개 검증"
   - 경제성 가정값이 비었으면 → "성능·경제성 평가에서 가정값 입력"
   - 저장된 결과가 입력 변경으로 무효이면 → "재평가 필요"

## 3. 데이터 준비 — 플랜트 데이터 요청 체크리스트 (메뉴 2)

### 3.1 표시 원칙
- 화면 제목 옆에 **"계획서 기반 초안"** 배지. 안내문: "사내 데이터 요청 양식 전체가 아니라, 계획서에 적힌 범주를 바탕으로 만든 초안입니다."
- 범주 7개 (항목 목록은 [03 §3](03_data_model.md)):
  1. 가스터빈 정보
  2. 연료 및 배기가스 운전 데이터
  3. 급수 및 증기 운전 데이터
  4. 배출가스 운전 데이터
  5. 열교환 모듈 사양과 설계값
  6. 핀치·어프로치 평가 항목 (드럼 압력, 절탄기 출구 급수 온도, 증발기 출구 가스 온도)
  7. 일정과 현장 조건

### 3.2 항목 필드
| 필드 | 설명 |
|---|---|
| 이름 | 초안 항목명 (한/영) |
| 값 | 문자열. 비어 있으면 `null` (0으로 바꾸지 않음) |
| 단위 | 초안 기본 단위, 사용자가 수정 가능 |
| 측정 위치 또는 조건 | 자유 입력 (예: "부하 100%, 굴뚝 입구") |
| 측정 시점 | 날짜·시간 |
| 메모 | 자유 입력 |
| 수신 상태 | `미수신` / `수신` / `검증 완료` |
| 필수 여부 | 평가 기능별 표시 (아래 3.4) |

### 3.3 상태 규칙
- 기본값은 `미수신`.
- 값을 입력해도 **자동으로 상태를 바꾸지 않습니다.** (값 입력 시 "상태를 '수신'으로 바꾸시겠어요?" 안내만 표시)
- `검증 완료` 는 사용자가 직접 선택해야 합니다. 값이 비어 있는 항목은 `검증 완료` 로 바꿀 수 없습니다(서버에서 400).
- 상태는 색상과 텍스트를 함께 표시합니다 (미수신 회색, 수신 파랑, 검증 완료 초록).

### 3.4 필수 여부 (평가 기능별)
- 평가 기능: `PERFORMANCE`(성능 평가), `PINCH_APPROACH`(핀치·어프로치), `ECONOMICS`(경제성)
- 항목마다 "어느 평가 기능에 필요한가"를 따로 표시합니다 (예: 성능 ●, 핀치 ○).
- 현재 기준은 확정되지 않았으므로 모든 필수 표시에 **"임시 기준"** 표시를 붙입니다.
- 경제성은 체크리스트 항목이 아니라 사용자 가정값으로 계산하므로 필수 체크리스트 항목이 없습니다.

### 3.5 부가 기능
| 기능 | 내용 |
|---|---|
| 미수신 필터 | 전체 / 미수신 / 수신 / 검증 완료 필터, 범주 필터 |
| 진행률 | 전체·범주별: `검증 완료 수 / 전체`, `수신 이상 수 / 전체` 두 가지를 막대와 숫자로 |
| 요청문 복사 | 미수신 항목을 범주별로 묶은 이메일용 본문을 서버에서 생성 → 클립보드 복사. 언어는 현재 UI 언어. 케이스명은 넣되 고객사·발전소 실명은 넣지 않음 |
| 저장 | 변경된 항목만 서버에 저장 (일괄 PATCH) |

요청문 예시 (한국어):
```
제목: [HRSG 평가] 플랜트 데이터 요청 — {케이스명}

안녕하세요. HRSG 성능·세정 검토를 위해 아래 데이터를 요청드립니다.
(측정 위치·조건과 측정 시점을 함께 알려 주세요.)

■ 가스터빈 정보
 - 가스터빈 모델명
 - 운전 부하 (%)
...
※ 본 목록은 계획서 기반 초안입니다.
```

## 4. 성능·경제성 평가 (메뉴 3)

화면 구성과 계산 규칙은 [02 §4](02_ui_ux.md), [05](05_calculation_and_demo_policy.md) 참조.
- 상단 모드 선택: **DEMO 시나리오** / **실제 평가**
- 섹션: ① 운전 상태 ② 예상 성능 손실·세정 후 회수 효과 ③ 공법별 비용·편익 비교(사용자 가정) ④ 핀치·어프로치 ⑤ 계산 정보(입력 조건, 단위, 계산 시점, 데이터 출처, 모델·데모 버전)
